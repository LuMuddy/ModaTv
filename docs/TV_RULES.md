# TV 交互规则（遥控器唯一输入）

本文是**验收标准**，不是建议。任何页面改动都要逐条对照；违反某条要在 PR 里说明理由。
手机/平板那套（滚动条、鼠标 hover、触摸拖动）在电视上不存在，不许作为设计依据。

---

## R1 焦点永远只有一个，且永远可见

- 每个页面进入时必须**主动请求首焦点**（`requestFocus` 放在两帧之后），不许让焦点空着等用户乱按。
- 首焦点 = 这一页最想让人按的那一项：首页第一张卡、详情页主 CTA、设置页第一行、播放页自绘焦点。
- 焦点样式统一：**3dp 白色描边 + 底色变化**；不许只靠"放大"表达焦点。
- **不许用 `scale` 表达焦点**：Compose 的 scale 只改绘制不改布局，Lazy 视口会把溢出裁掉
  （实测：tab 白框左边、网格首末行卡片上下沿都会缺一条边）。例外：没有任何滚动容器的裸按钮。

## R2 列表跟着"块"走，不跟"像素"走

- 焦点落到网格的某项 → 以**整行**为单位校正滚动；落到横向轨道的某项 → 以**整列（整格）**为单位校正。
- 上下各留 12~16dp 呼吸空间，被聚焦项不许贴视口边缘。
- 连按方向键必须跟得上：**用 `scrollBy` 立即滚，不用动画**。动画没走完下一下又来了，
  表现为「按了三下、画面还在追第一下」，用户会看到焦点行在屏幕外。
- 实现：`TvGridFocusScroll`（纵向网格）/ `TvRowFocusScroll`（横向轨道）。新列表页必须接其中之一。

## R3 每个可滚动区域的滚动轴只有一条

- 纵向网格里不许再套纵向滚动容器；横向轨道自己吃左右键，纵向仍归外层。
- `LazyVerticalGrid` / `LazyColumn` 在 `Column` 里必须用 `weight(1f)`，
  **不许 `fillMaxSize()`**：`Column` 给非 weight 子项的约束是整列高度，视口会比屏幕长出一截，
  末行就贴到屏幕外被切。

## R4 按键语义分层（最上层先接管）

- 顺序：**浮窗面板 → OSD 控制条 → 页面 → 应用**。返回键逐层退出，不许直接 finish。
- 浮窗展开后它就是最上层：左右键按该浮窗的导航轴分派（横向档位条换值、纵向列表静默），
  不许"所有浮窗一律忽略左右键"。

## R5 选中态与焦点态是两套视觉

- 焦点 = "遥控器现在停在哪"；选中 = "当前生效/当前分类/当前档位"。
- 两者必须能同时看出来：焦点态优先显眼，选中态用底色/下划线/勾标保留。
- 基准：`#2A5FD6`（选中蓝）与 `#FFFFFF`（焦点白）不许混用。

## R6 字号与对比度按 3 米观看距离

- 正文 ≥ 18sp，辅助信息 ≥ 14sp，**12sp 及以下只允许出现在非关键信息上**。
- 可聚焦元素内的文字必须跟随内容色（`LocalContentColor`），不许硬编码；
  `TvTitle/TvBody/TvCaption` 里烤死了颜色，聚焦白底上必须显式覆盖。
- 白底 + 白字 = 1.00:1，属于全盲，任何状态都不许出现。

## R7 系统栏

- 应用必须整屏沉浸：启动即 `hide(systemBars())`，**并且每次窗口重新获得焦点都要再 hide 一次**
  （下拉通知栏/切后台回来会把它放出来，顶部一行状态栏会压住工具栏）。
- 不许给页面加"顶部安全边"来绕这个问题。

## R8 首帧不闪、不跳

- 数据未到时给加载态，不许先画一版错布局再跳。
- 焦点滚动、状态切换不许让页面整体上下跳（布局高度要可预测：固定卡高、固定行高）。

## R9 空态/错误态也要能操作

- 空态里的"重新加载"必须拿到首焦点；没有任何可聚焦元素的页面要在设计上确认这是有意的（如"关于"页）。
